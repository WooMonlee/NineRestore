# 救援载荷更新与失效：手动验证清单（1.0.0-beta.1）

> 适用提交：`4b7f337` 及以后（`package` 已接入 `payload-gate`）。
> 目的：在**真实机**上逐条确认"旧载荷被识别并重写 / 写不进去时明确失败"，以及两项只能在
> 物理机做的验收。每步都写"期望看到什么"；**没看到就是没通过**，不要用"应该没问题"代替记录。
>
> 记号：**[物理机]** = 虚拟机做不了，必须在真实硬件上做；其余可在 VM 或真实机做。

## 0. 准备与基线（先做完再开始）

1. 用 `4b7f337` 或更新提交执行 `make package`；确认 `dist\bootfiles\rescue-build.txt`
   内容为 `1.0.0-beta.1`（一行，末尾换行）。
   - **期望看到**：文件存在且内容与 `dist\version.json` 的 `"version"` 完全一致。
2. 记录本次载荷基线（后续每一步都用它对照）：
   - `dist\bootfiles\initramfs-zjrestore.cpio.gz` 的字节数（本轮构建为 `17,392,733`）；
   - `dist\bootfiles\vmlinuz-zjrestore` 的字节数（本轮构建为 `12,142,528`）；
   - 两者的 SHA256（`make sha256` 后看 `dist\SHA256SUMS.txt`）。
   - **期望看到**：`make dist-check` 输出 `check-dist: PASS (dist)`。
3. 准备一台 **UEFI** 真实机（有 ESP、能进 Windows、有管理员权限），并确认可以回滚
   （系统备份/快照/PE 启动盘至少有一种）。
4. 打开主界面「日志」导出的收集包路径与程序目录 `logs\`，后面要看日志行。

## A. 真实机 ESP 里是 0.9.x 旧载荷 → 装新菜单

1. 以管理员打开命令提示符，挂载 ESP：
   ```
   mountvol X: /s
   type X:\EFI\ZJRESTORE\rescue-build.txt
   dir X:\EFI\ZJRESTORE\initramfs-zjrestore.cpio.gz
   ```
   - **期望看到**：`rescue-build.txt` 为 `0.9.x`（例如 `0.9.92` / `0.9.96`），
     initramfs 字节数**小于**第 0 步记录的新载荷字节数。
   - 若 ESP 上根本没有 `EFI\ZJRESTORE\`，本项不适用，改做"首次安装"路径（应直接写新版，
     日志不应出现 stale→rewrite）。
2. 运行 `dist\SysRecoverUI.exe`（管理员），选好镜像与目标分区 C:，点「安装菜单」，
   在确认框里确认，等待完成。
   - **期望看到**：界面提示安装成功（不是"部分成功/失败"）。
3. 在同一次操作的日志里按顺序找到这几行（`SysRecover-*.log`）：
   ```
   ESP rescue payload: build=0.9.x initramfs=<旧字节数> (builtin=1.0.0-beta.1 <新字节数>)
   ESP rescue payload stale -> rewrite (backup before write)
   backup dir: X:\EFI\ZJRESTORE\backup-pre-rewrite-YYYYMMDD-HHMMSS (N files)
   ```
   - **期望看到**：`build=` 是旧版本、`builtin=` 是新版本；`stale -> rewrite` 存在；
     `backup dir:` 的路径真实存在且 `N files` > 0。
   - 说明：装菜单走 `InstallUefiBootEntry` 的 `CopyOne`，成功复制**不**逐文件打印；
     落盘是否真的更新，以第 4 步的文件复核为准。失败时才会出现
     `copy <文件> failed err=<n>` 与 `copy UEFI rescue files FAIL`。
4. 复核 ESP 落盘结果：
   ```
   type X:\EFI\ZJRESTORE\rescue-build.txt
   dir X:\EFI\ZJRESTORE\initramfs-zjrestore.cpio.gz
   dir X:\EFI\ZJRESTORE\backup-pre-rewrite-*
   ```
   - **期望看到**：`rescue-build.txt` 变为 `1.0.0-beta.1`；initramfs 字节数与第 0 步记录
     **完全相同**；备份目录里有旧的 `initramfs-zjrestore.cpio.gz`、
     `vmlinuz-zjrestore`（或 `vmlinuz-zjrestore.efi`，取决于该机启动链）和
     `firmware-boot.txt`。
5. 卸载 ESP：`mountvol X: /d`。
   - **期望看到**：命令成功，资源管理器里 X: 消失。

**判定**：第 3、4 步任一行/任一文件不符 → 本项 FAIL，保留日志与 ESP 目录清单再报。

## B. ESP 只读 / 写满 → fail-closed（提示含双方版本）

### B1. 写满（可自动化，优先做）

1. 挂载 ESP：`mountvol X: /s`，查看剩余空间：`dir X:\`。
2. 用大文件占满剩余空间，直到剩余空间 **小于 33 MB**（新载荷 initramfs + vmlinuz ≈ 29.5 MB，
   再留启动项写入余量）：
   ```
   fsutil file createnew X:\zjfill.bin <字节数>
   dir X:\
   ```
   - **期望看到**：`rescue-build.txt` 仍是旧版本 `0.9.x`；`dir` 显示可用字节 < 33,554,432。
3. 保持 ESP 挂载，运行 `dist\SysRecoverUI.exe` 再点「安装菜单」（或直接执行修复引导，
   见 C 节）。
   - **期望看到**：操作**失败并明确提示**。空间预检先报一行，形如：
     ```
     ESP 空间不足：还需 <net>MB，另需预留 16MB 给 bcdboot，可用 <free>MB。请清理 ESP 上的其它文件，或换用更小的 initramfs。
     ```
     随后**必须**再出现含**两个版本号**的失败文案，形如：
     ```
     ESP 上为旧版救援环境（0.9.x），内置为 1.0.0-beta.1，需更新后重试。
     ```
   - **期望看到**：日志同时有 `ESP space: need(net) … free …` 与上面那条双方版本文案；
     若是拷贝阶段失败（空间够但写入被拒），则出现 `copy <文件> failed err=<n>` /
     `copy UEFI rescue files FAIL`，同样必须带双方版本。
4. 复核：
   ```
   type X:\EFI\ZJRESTORE\rescue-build.txt
   bcdedit /enum firmware
   ```
   - **期望看到**：`rescue-build.txt` **仍是 0.9.x**（没有被写成新版 = 没有"半成功"）；
     固件启动项里**没有新增**指向本工具的条目（安装失败不应留下新 Boot####）。
5. 清理：`del X:\zjfill.bin`，再 `mountvol X: /d`。
   - **期望看到**：删除成功；卸载后 X: 消失。

### B2. 只读（取决于硬件，做不了就如实记"未执行"）

1. 让 ESP 处于**真实写保护**：优先用带写保护开关的 USB/SD 介质（且被固件当作系统盘启动），
   或用固件/硬件提供的磁盘写保护。`diskpart` 的 `set readonly` 对系统 ESP 通常不生效，
   **不要**把"命令返回成功"当成写保护已生效。
2. 在写保护状态下重复 B1 第 3 步。
   - **期望看到**：与 B1 相同 —— 失败提示含双方版本；ESP 上 `rescue-build.txt` 不变。
3. 复核：`mountvol X: /d` 后确认 X: 消失。
   - **期望看到**：写保护期间没有任何文件被改写（可用第 0 步 SHA256 对比）。

**判定**：若提示里只有"失败"而没有双方版本，或 `rescue-build.txt` 被改成新版但内容不完整，
均判 FAIL。B2 无硬件条件时记"未执行（缺写保护介质）"，不得记"通过"。

## C. 同一条件下跑 `repair-boot`

1. 保持 A 节的旧载荷条件（若已做完 A，需先把 ESP 再恢复为旧载荷；做不到就换一台旧载荷机器）。
2. 以管理员运行：
   ```
   dist\SysRecover.exe repair-boot
   ```
   - **期望看到**：退出码 0；日志出现
     ```
     repair-boot rescue payload: ESP rescue payload: build=0.9.x initramfs=<旧> (builtin=1.0.0-beta.1 <新>)
     ESP rescue payload stale -> rewrite
     backup dir: X:\EFI\ZJRESTORE\backup-pre-refresh-YYYYMMDD-HHMMSS (N files)
     rewritten X:\EFI\ZJRESTORE\initramfs-zjrestore.cpio.gz
     ```
     随后 `rescue-build.txt` 变为 `1.0.0-beta.1`，initramfs 字节数 = 第 0 步记录值。
3. 再在"ESP 写满"条件下执行同一条 `repair-boot`。
   - **期望看到**：退出码 **1**；日志含双方版本文案；若已有部分文件被刷新，日志还有
     ```
     refreshed files left in place; rescue payload NOT updated in full
     ```
   - **期望看到**：`rescue-build.txt` 仍为旧版本（自报版本没有"假装更新"）。
4. 记录 `bcdedit /enum firmware` 前后差异。
   - **期望看到**：失败时没有新增/删除任何本工具的固件启动项。

**判定**：成功路径必须同时满足"rc=0 + stale→rewrite + 备份目录 + 版本戳变新 + 字节数一致"；
失败路径必须同时满足"rc=1 + 双方版本提示 + 自报版本保持旧"。缺一项即 FAIL。

## D. 真实 USB 固定盘（**[物理机]**）

1. 接入一块**固定盘类型**的 USB 硬盘（不是 U 盘/可移动盘），打开主界面「显示 USB 设备」前的
   设备列表。
   - **期望看到**：默认**看不到**该 USB 固定盘（只列内置盘）。
2. 勾选「显示 USB 设备」（或对应开关）后重新打开下拉。
   - **期望看到**：该盘出现，容量/盘符正确，并可被选中；取消勾选后再次消失。
3. 选中该盘做一次**只读到预检**（不格式化），或仅打开分区下拉。
   - **期望看到**：盘符与分区信息与实际一致；没有把该盘误标成内置盘。
4. 记录设备类型（固定/可移动）与界面标注是否一致。

**判定**：默认可见、或勾选后仍不可见/容量错，均判 FAIL。此项**只能物理机**做。

## E. BIOS/MBR 机型（**[物理机]**）

1. 找一台 **BIOS（非 UEFI）+ MBR** 的真实机（或可切换为 Legacy/CSM 的机器）。
2. 运行 `dist\SysRecover.exe repair-boot`，记录日志。
   - **期望看到**：走 BIOS 分支（`repair-boot self-contained BIOS` 或
     `repair-boot bcdboot (BIOS)`），且最终结果明确；若引导未能修好，回执为
     `OK_BOOT_UNFIXED`（不是"还原成功"）。
3. 打开主界面装一次「安装菜单」，重启进 BCD 菜单。
   - **期望看到**：菜单里出现本工具条目，选中后能进救援层；返回 Windows 后
     `bcdedit /enum {current}` 正常。
4. 若机器有 `{bootmgr} timeout=0`，先按 `docs/25` PIT-094 的说明把 timeout 调大再测。
   - **期望看到**：菜单停留可按键；不是"按什么键都直接进 Windows"。

**判定**：UEFI 机器无法验证本项；VM 也不能替代，必须在 BIOS/MBR 物理机上做。
失败时保留 `boot-cd` 日志、`bcdedit /enum all` 输出与照片。

## F. 主窗置后观察（可选，配合 `docs/34` N19）

1. 「导出驱动」成功 → 提示框点「确定」。
   - **期望看到**：资源管理器自动跳到前台并选中新单文件；主窗在其后（这是现状）。
2. 点任务栏「九转还原」→ **期望看到**：主窗回前台，按钮可正常点击。
3. 任意确认框关闭后立刻点任务栏其它窗口再点回主窗 → **期望看到**：主窗能正常回到前台。
4. 若出现"关闭确认框后主窗仍在其它窗口后面"，记录时间、当时前台窗口、是否刚打开过
   资源管理器/浏览器，并连同日志交回（对应 N19 的时序类缺陷）。
